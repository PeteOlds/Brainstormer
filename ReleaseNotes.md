# Release Notes

Human-readable record of shipped releases for Brainstormer. **Update this file on every release** with the version, date, and a summary of features and bug fixes delivered.

- For detailed, per-commit history see `CHANGELOG.md`.
- Per-app/per-release artefacts generated by the product live in `docs/release-notes/`.

## How to add an entry

1. Add a new section at the top: `## vX.Y.Z — YYYY-MM-DD`.
2. List **Features** and **Bug fixes** (omit a subsection if empty). Note breaking changes clearly.
3. Keep entries factual and user-facing; link issues/IDs where helpful.

## v0.93.1 — 2026-11-16

### Bug fixes
- **Blank page at /login fixed:** the Flutter web build loaded CanvasKit from `https://www.gstatic.com/flutter-canvaskit/...`, which the app's Content-Security-Policy blocks (`script-src`/`connect-src` allow `'self'`). The engine never started, so the page stayed blank with CSP errors in the console. Web builds now use `--no-web-resources-cdn`, serving CanvasKit same-origin from `build/web/canvaskit/` — no external CDN, works on a LAN and offline.
- **Build step is now guarded:** added `scripts/build_web.sh`, which always passes the required flag, and documented it in `AGENTS.md` so a plain `flutter build web` cannot reintroduce the blank page.

## v0.93.0 — 2026-11-16

### Features
- **Multi-select ideas and change state in bulk:** the Ideas list now has a selection mode (admin only). Tick several ideas — or "select all" on the page — then choose a new state once. The server applies legal transitions and reports any skipped ones, so a mixed selection no longer needs one-by-one changes.
- **Bulk endpoint wired to the UI:** the app now uses `PATCH /api/v1/ideas/bulk-status`, which already existed server-side but had no client.

### Bug fixes
- **Idea detail no longer fails to load:** the detail endpoint returned the viewer's user id in `user_vote` instead of their vote (1/-1/null). The Flutter client parses `user_vote` as a number, so a UUID crashed the page with `type 'String' is not a subtype of type 'num?'`. All five affected responses (detail, status change, chat, iterate, edit) now send the real vote.
- **Detail parsing is now defensive:** non-numeric counts, a non-map `output`, or malformed `actions`/`edit_history` sections are ignored instead of blanking the whole page.
- **Admin no longer shows the navigation twice:** for users without the global admin role, the admin route wrapped `IdeasPage` in a second `AppShell`. It now renders the page's own shell once.
- **Settings is admin-only:** the Settings screen exposes instance AI provider keys and budgets. It is now hidden from the nav rail and drawer for regular users and gated at the route.
- **App footer shows the real version:** `kAppVersion` was stuck at `0.47.0`; it now mirrors `VERSION`, and `pubspec.yaml` is bumped in step so the Flutter build number matches the backend.

### Tests
- Flutter: 30 tests pass (new coverage for the bulk-select flow, nav gating, and lenient payload parsing).
- Backend: full suite green, coverage 75.32%.

## v0.92.2 — 2026-11-16

### Bug fixes
- **Release readiness recognises the current Test-tab names:** the pre-release gate now matches "Check the main screen loads in a browser" and "App's automated tests pass", not only the retired `UI:`/`Generated test suite passes` wording, so a release with real test results is no longer blocked.
- **"Run release" accepts a bodyless request:** `POST /releases/<id>/pipeline` tolerates a missing JSON body instead of returning `415 Unsupported Media Type`.
- **Build-test assertions updated:** integration tests now assert the current user-facing test names instead of the retired `UI:` prefix.

### Test coverage
- Added unit tests for the build test runner (`app/tasks/test_tasks.py`) and the static-file/API proxy (`app/services/frontend_proxy.py`), lifting total coverage above the 75% gate (75.32%).
- The full suite is green: no failures, no errors.

## v0.92.1 — 2026-11-16

### Bug fixes
- **Tests no longer inherit deployment TLS:** `TestingConfig` clears `TLS_CERT_FILE`/`TLS_KEY_FILE`, so a `.env` that enables HTTPS for the live app can no longer make the HTTP test client and Playwright servers answer TLS. Fixes `ERR_SSL_PROTOCOL_ERROR` and login-fixture failures across the suite.
- **UI harness pinned to HTTP:** the Playwright `live_app` fixture now explicitly clears TLS cert/key config, keeping browser tests on plain HTTP regardless of repo `.env` state.
- **Flaky dashboard filter test:** the status-filter UI test now waits for the filter to apply rather than sleeping a fixed 800 ms.

## v0.92.0 — 2026-11-16

### Features
- **Flutter web app at /:** Brainstormer now serves the Flutter web build at the root path (`/`), with same-origin `/api/v1/*` unchanged. Jinja remains available under `/jinja/*` as an emergency fallback.
- **Version parity:** Flutter `pubspec.yaml` now mirrors backend `VERSION` (0.91.0 -> 0.92.0 with this release) so the app footer matches the backend.
- **Deployment wiring:** Added `FLUTTER_WEB_ROOT` env var; Flask statically serves `flutter/build/web` and falls back to `index.html` for client-side routes.

### Breaking changes
- The default root application is now the Flutter web build, not the legacy Jinja UI. Jinja routes are moved under `/jinja/*` (e.g. `/jinja/login`, `/jinja/ideas`). Set `LEGACY_WEB_ENABLED=True` only to keep Jinja visible under those paths.

## v0.91.0 — 2026-11-16

## v0.90.1 — 2026-11-16

### Bug fixes
- Admin Dashboard instance details now show for any instance the user administers, even when the request is unscoped. Previously, unscoped instance admins only saw the currently scoped instance (or none), so e.g. Site 90 Test Admin saw no details until they scoped the session. Server-side scoping still prevents seeing or editing instances the user is not an admin of.

## v0.90.0 — 2026-11-16

### Features
- **Instance Free/Paid details (site admin):** site administrators can view and edit an instance's plan status, renewal date (auto-set to 12 months from Free→Paid transition but editable), comment, payment reference, amount paid with ISO currency (default NZD), paid by, promotional and charitable flags.
- **Admin dashboard instance details:** Admin Dashboard now shows instance plan/billing details; instance administrators see their own instance read-only; site administrators can edit any instance from the same card.
- **System Settings cleanup:** removed the non-functional AI Connections placeholder from System Settings (AI Settings remain at `/admin/ai`).
